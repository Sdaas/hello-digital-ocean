# Session retro — 2026-08-10

## Session summary

Entered `/sdlc-newproject` for **hello-digital-ocean** (shell/cli). Discovered
that approved upstream artifacts (`discovery/`, `architecture/` with 7 ADRs,
`PROGRESS.md`) were already present — this is the expected hand-off from
`/sdlc-discovery` → `/sdlc-architecture`, but the scaffold flow treated the
non-empty directory as an anomaly. Backed up and checksummed the existing
artifacts, scaffolded the shell/cli skeleton with `--force`, and verified zero
artifact loss. Then **renamed** the main control CLI `hello-digital-ocean` →
`digital-ocean` and named the reference chatbot the **`demo` app**, created
`demo/` and `infra/` skeleton dirs, and propagated the new names through **all**
docs including the 7 ADRs (with dated traceability notes). Ran a dedicated
consistency review that caught and fixed invocation-style drift and five
un-qualified `requirements.txt` references. Filed two workflow feedback issues
during the session (#106, #107). Ended at the pre-commit gate — **nothing
committed** (rule #10 held throughout).

## What went wrong / friction

- **Greenfield assumption fought the hand-off.** `/sdlc-newproject` (and
  `scaffold.sh`) assume an empty target, but by the time it runs the discovery +
  architecture artifacts are the *expected* state. The agent had to stop, back
  up, and `--force` — a designed-in surprise. → filed **#106**.
- **No canonical home for tooling feedback.** `/sdlc-feedback` about the SDLC
  itself required discovering a local clone of `claude-sdlc` and inspecting its
  git remote to find where to file — fragile; only worked because the clone
  happened to be present. → filed **#107**.
- **Naming decided too late.** The binary name, entry-point location, and
  invocation model were never pinned as architectural decisions, so a
  one-line-early choice became a rename sweep across ~13 approved docs after
  scaffolding.
- **Rename rippled silently.** Moving the entry point from repo-root `./demo` to
  `bin/digital-ocean` broke the invocation model (bare `digital-ocean <cmd>`
  assumes a PATH install nothing provided) — caught only by the consistency pass.

## Which gate or command

- **`/sdlc-newproject` Step 3 (Scaffold)** + `sdlc-common/scaffold.sh` —
  empty-dir assumption; no awareness of expected upstream artifacts.
- **`/sdlc-feedback` Gate 1 (target-repo resolution)** — no known tooling-repo
  address.
- **`/sdlc-architecture` (naming/entry-point)** — name + invocation model not
  captured as an ADR, so they drifted into scaffold time.

## Proposed SDLC improvements

- Make `/sdlc-newproject` **discovery-aware**: detect and preserve
  `discovery/` + `architecture/` + `PROGRESS.md` as the normal hand-off. (#106)
- Give `/sdlc-feedback` a **canonical tooling-repo constant** so feedback routes
  without a local clone. (#107)
- Have `/sdlc-architecture` **pin the artifact name + entry-point/invocation
  model as an ADR before scaffold.** (#108)
- Promote **back-up + checksum before any `--force` scaffold** to a standard,
  documented step in `/sdlc-newproject` / `scaffold.sh`. (#109)

## What went well (keep)

- **Back-up + checksum before `--force`** proved byte-for-byte that no approved
  artifact was lost.
- **Review-before-commit held** — every gate paused for human approval; nothing
  committed.
- **Dedicated consistency-review pass after the rename** caught real drift
  (invocation style, 5× `requirements.txt`) a spot-check would have missed.
- **Dated traceability notes** ("Rename (2026-08-10)…") kept edits to approved
  artifacts auditable rather than silent.
